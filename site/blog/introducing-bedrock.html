Introducing Bedrock

2026-08-17

Bedrock is an imperative, statically typed systems programming language. We are building it because we believe a systems language can be small without being primitive, and safe without being slow.

The rules are simple. Every feature must be easy to understand, easy to implement, and must genuinely improve systems programming. If a feature fails any of those tests, it does not ship. That is the whole design process.

Concretely, Bedrock stands on four legs:

  • Regions for memory. Scoped arenas, bulk-freed on exit, checked at compile time by a simple escape rule. No malloc, no free, no garbage collector.
  • Explicit failure. Functions that can fail say so in their return type with !. Optional values say so with ?. Nothing fails silently.
  • Safety by default, escape hatches on purpose. Low-level operations exist, but only inside unsafe blocks that reviewers can grep for.
  • Procedures and functions. A proc does work; a func returns a value. The distinction is small and it makes code easier to read.

The documentation and the full grammar are on this site. The language is a draft and moving quickly — feedback is welcome.
